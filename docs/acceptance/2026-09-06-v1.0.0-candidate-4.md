# v1.0.0 hardware-qualification candidate 4

Status: qualification in progress; physical baseline confirmation pending

This record fixes the artifacts used for the fourth stable hardware-
qualification candidate. It is not yet a hardware-acceptance record and does
not authorize a Compatibility Release. Any source or image change creates a
different candidate and requires the applicable checks to be repeated.

Candidate 4 replaces candidate 3. It adds bounded, site-scoped Fleet delivery
reads and makes PrintHub reconcile each logical job with every downstream page.
This removes the stale `queued` state observed after candidate 3 had physically
printed successfully.

## Recreated-stack baseline

The existing `printhub-qualification` volumes were retained while the services
were recreated from the candidate digests. No print job was submitted during
the update.

- all eight services are running and every defined healthcheck is healthy;
- PrinterFleet API and worker run as UID 10001, PrintHub as UID 10001,
  PrintAgent as UID/GID 999 and the consoles as their unprivileged users;

  `no-new-privileges`; PrinterFleet, its worker, PrintHub, PrintAgent and Fleet
  Console additionally use read-only root filesystems;
- the public PrintHub catalog exposes only `zebra-lp2824-usb`, makes it the
  default and reports loaded 50 x 25 mm media;
- the official CUPS `get-printer-attributes.test` passed against the recreated
  IPP service;
- reading the persisted candidate-3 baseline through the new PrintHub changed
  its formerly stale logical snapshot to `transport_accepted`, 238 bytes, one
  downstream entry and the matching Fleet delivery ID.
