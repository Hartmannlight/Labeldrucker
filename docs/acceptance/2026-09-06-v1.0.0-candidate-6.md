# v1.0.0 hardware-qualification candidate 6

Status: qualification in progress; browser image output pending

This record fixes the artifacts used for the sixth stable hardware-
qualification candidate. It is not yet a hardware-acceptance record and does
not authorize a Compatibility Release. Any source or image change creates a
different candidate and requires the applicable checks to be repeated.

Candidate 6 replaces candidate 5 because Chrome landscape pages required a
tolerance-bounded orientation correction, the IPP queue did not expose an
operator-facing image policy, and Fleet promoted the Agent's initial `queued`
response too early.

## Deployed capability evidence

The persistent `printhub-qualification` volumes and unchanged Agent, Studio and
PostgreSQL services were retained. PrinterFleet, its worker, PrintHub, the IPP
gateway and the root-versioned Fleet Console run from the exact digests above.
All eight services run and every defined healthcheck is healthy.

The live CUPS IPP conformance probe passed without submitting a print job. It
reported exact borderless 50 x 25 mm media, monochrome output, 203 dpi, all four
standard orientations and `print-quality-supported= draft, normal, high`. The
existing Windows Microsoft IPP Class Driver queue still has an exact 50 x 25 mm
user ticket and zero queued jobs. Its refreshed PrintCapabilities expose
`Draft`, `Normal` and `High` output quality.

The mapping is:

- `Draft`: text/graphics threshold without dithering;
- `Normal`: automatic PrintHub content policy;
- `High`: photo policy with Floyd-Steinberg dithering.

Chrome may hide this standard option in its simplified dialog. The Windows
system dialog opened with `Ctrl+Shift+P` is the authoritative operator surface.
PrintHub also recognizes the observed approximately 25.025 x 50.049 mm Chrome
landscape page as the rotated form of 50 x 25 mm. Other media mismatches remain
held and require an explicit fit/fill decision.
