# v1.0.0 hardware-qualification candidate 5

Status: superseded after physical baseline confirmation

This record fixes the artifacts used for the fifth stable hardware-
qualification candidate. It is not yet a hardware-acceptance record and does
not authorize a Compatibility Release. Any source or image change creates a
different candidate and requires the applicable checks to be repeated.

Candidate 5 replaces candidate 4 only because PrintAgent restart recovery
discarded a previously durable `transport_accepted` observation. The other
component artifacts are unchanged from candidate 4.

readable and writable. All eight services run, every defined healthcheck is

After a normal Agent container restart, the durable Agent job remained
`transport_accepted` with the same timestamp, hash and byte count. Repeating
the complete PrintHub request with the same idempotency key returned the same
PrintHub and Fleet identifiers. A direct durable-boundary count found exactly
one matching Fleet delivery with one attempt and exactly one matching Agent
job. The restart and repeat therefore neither requeued nor created a second
delivery. The operator confirmed that the single label marked `CANDIDATE 5`
was emitted. The durable restart/repeat checks found no second Fleet or Agent
record; a separate explicit physical duplicate count was not recorded.

Candidate 5 is superseded because follow-up browser image testing exposed two
issues that require new artifacts. Portrait image output succeeded, while two
Chrome landscape submissions were safely held: Windows supplied approximately
25.025 x 50.049 mm for the loaded 50 x 25 mm medium. The next candidate accepts
only this tolerance-bounded width/height swap as an automatic rotation. Chrome
also exposed no dedicated dithering control, so the next IPP artifact maps the
standard draft/normal/high print-quality choices to text/automatic/photo raster
policy.
